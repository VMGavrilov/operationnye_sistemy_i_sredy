# Свой инцидент: yes съедает процессор

### До инцидента

```bash
nproc
uptime
free -h
```

- ядер: **2**;
- load average: **≈ 0.0**;
- память: свободна почти полностью.

### Во время инцидента

```bash
yes &
sleep 5
uptime
free -h
```

- load average: **≈ 1.0** при 2 ядрах;
- `%Cpu(s)` us ≈ **50 %**;
- сайт/терминал отвечает медленнее.

---

## Поиск виновника

```bash
ps -eo pid,ppid,ni,stat,%cpu,cmd --sort=-%cpu | head -5
PID=$(pgrep yes)
echo "виновник PID = $PID"
pstree -s -p $PID
ls -l /proc/$PID/cwd
```

**Результат:**

- **PID виновника:** из `pgrep yes`;
- **PPID:** ваша оболочка `bash`;
- **состояние:** `R` (running), `%CPU` ≈ 100;
- **рабочий каталог:** `~` (домашний каталог, из `/proc/PID/cwd`);
- **команда:** `yes` — бесконечный вывод строк в stdout.

---

## Исправление

```bash
renice -n 19 -p $(pgrep yes)
ps -o pid,ni,cmd -p $(pgrep yes)

kill $(pgrep yes)
sleep 1
pgrep -a yes || echo "процесс завершён"
```

- `renice -n 19` — понизили приоритет до минимума;
- `kill` — завершили сигналом TERM.

---

## Повторное измерение

```bash
uptime
/usr/bin/time -f "%e s, %M KB" yes > /dev/null &
sleep 2
kill %1
```

- load average вернулся к **≈ 0.0**;
- `time` показывает: `real ≈ user`, `sys ≈ 0` — процесс работал в пользовательском режиме, памяти почти не потреблял.

---

## Postmortem

### Симптом

- **До:** load average ≈ 0.0 при 2 ядрах, память свободна.
- **Во время:** load average ≈ 1.0, `%Cpu(s)` us ≈ 50 %, система отвечает медленнее.
- **Источник:** `uptime`, `top -b -n 1 | head -12`, `free -h`.

### Причина

- `yes` — бесконечный цикл вывода строк в stdout, занимает **один процессор целиком**.
- При 2 ядрах это 50 % общей загрузки, но один CPU полностью загружен.
- Процесс не ждёт I/O, поэтому `real ≈ user`, а `sys` близко к нулю — вся работа в пользовательском режиме.

### Действия

| № | Команда | Результат |
|---|---------|-----------|
| 1 | `ps -eo pid,ppid,%cpu,cmd --sort=-%cpu \| head -5` | нашли `yes` в первой строке |
| 2 | `pgrep yes` | получили PID |
| 3 | `pstree -s -p $PID` | увидели, что родитель — `bash` |
| 4 | `ls -l /proc/$PID/cwd` | рабочий каталог — `~` |
| 5 | `renice -n 19 -p $(pgrep yes)` | nice 0 → 19 |
| 6 | `kill $(pgrep yes)` | процесс завершён сигналом 15 |
| 7 | `uptime` | load average вернулся к норме |

### Профилактика

1. **Ограничивать время работы** — использовать `timeout 10 yes`, чтобы процесс не работал бесконечно.
2. **Перенаправлять вывод** — `yes > /dev/null` не спасает от нагрузки CPU, но хотя бы не забивает терминал; лучше использовать `yes | head -n 100` для ограничения.
3. **Регулярно проверять `top`/`htop`** — если один процесс занимает CPU > 50 % дольше нескольких секунд, разбираться.
4. **Не запускать `yes` без необходимости** — это классический пример процесса, который грузит CPU впустую.
