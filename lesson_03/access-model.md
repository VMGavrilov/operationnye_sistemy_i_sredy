# Модель доступа проекта

## Роли

| Роль | Описание | Группы |
|------|----------|--------|
| lead | руководитель разработки: код, отчёты, администрирование | mobile-dev, mobile-qa, sudo |
| dev | разработчик: пишет код | mobile-dev |
| qa | тестировщик: пишет отчёты | mobile-qa |
| guest | внешний сотрудник: без доступа | только личная группа |

## Ресурсы

| Ресурс | Путь | Группа | Права | Доступ |
|--------|------|--------|-------|--------|
| Исходный код | /srv/mobile/src | mobile-dev | 2770 | lead, dev |
| Отчёты тестирования | /srv/mobile/reports | mobile-qa | 2770 | lead, qa |

## Принципы

1. **Минимальные привилегии** — каждая роль получает только те группы, которые нужны для работы.
2. **Разделение обязанностей** — разработчик не может менять отчёты, тестировщик — код.
3. **Изоляция внешних** — guest не входит ни в одну проектную группу.
4. **Администрирование** — только lead входит в sudo.
